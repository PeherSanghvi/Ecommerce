🔴 PROBLEM
──────────────────────────────────────────────────────────────────────────────
Error when placing order:
  "Cast to ObjectId failed for value 'user-1784813145539' (type string)"

This fake ID format "user-1784813145539" is NOT a MongoDB ObjectId.
It's an invalid user identifier that causes database errors.

───────────────────────────────────────────────────────────────────────────────

🔍 ROOT CAUSE ANALYSIS
──────────────────────────────────────────────────────────────────────────────

ROOT CAUSE #1: Stale localStorage Data (Most Likely)
  ├─ Old session stored fake user ID in browser localStorage
  ├─ Browser persistent storage loaded on page refresh
  ├─ UserContext initialized with this corrupted data
  └─ Result: user._id = "user-1784813145539"

ROOT CAUSE #2: Login Failure Not Caught
  ├─ API call to login endpoint failed silently
  ├─ User state was never updated
  ├─ Previous fake/temporary user remained active
  └─ Result: Checkout sent invalid ID to backend

ROOT CAUSE #3: No Validation on Either Side
  ├─ Frontend didn't validate user ID format before sending
  ├─ Backend validator was too lenient (accepted any string)
  ├─ Service layer didn't validate before User.findById()
  └─ Result: Invalid IDs reached database query

───────────────────────────────────────────────────────────────────────────────

✅ SOLUTION IMPLEMENTED
──────────────────────────────────────────────────────────────────────────────

LAYER 1: FRONTEND VALIDATION (PaymentMethodStep.jsx & Checkout.jsx)
  ├─ Function: isValidMongoDBObjectId(id)
  ├─ Check: Is ID exactly 24 hexadecimal characters?
  ├─ If INVALID:
  │   ├─ Clear localStorage of corrupted user data
  │   ├─ Show error: "Session expired. Please login again."
  │   └─ STOP (don't call API)
  └─ If VALID: Continue to API call

LAYER 2: BACKEND VALIDATOR (orderValidator.js)
  ├─ Enhanced customerId validation
  ├─ Check: Is string exactly 24 hex characters?
  ├─ If INVALID:
  │   ├─ Return HTTP 400 Bad Request
  │   ├─ Message: "Invalid customer ID format. Must be a valid MongoDB ObjectId"
  │   └─ STOP validation
  └─ If VALID: Continue

LAYER 3: BACKEND SERVICE (orderService.js)
  ├─ Added format validation at entry point
  ├─ Check: Is ID valid MongoDB ObjectId format?
  ├─ If INVALID:
  │   ├─ Throw error with format details
  │   └─ Error bubbles to controller
  └─ If VALID: Continue to User.findById()

🎯 WHAT'S A VALID MONGODB OBJECTID?
──────────────────────────────────────────────────────────────────────────────

Format:
  ├─ Exactly 24 characters
  ├─ All hexadecimal (0-9, a-f, A-F)
  └─ No spaces, no special characters

Examples of VALID ObjectIds:
  ├─ "507f1f77bcf86cd799439011"
  ├─ "6509e5a8c2f1a2c3d4e5f6a7"
  └─ "000000000000000000000001"

Examples of INVALID ObjectIds (will be REJECTED):
  ├─ "user-1784813145539"         ✗ (has prefix, wrong format)
  ├─ "temp-user"                  ✗ (not numeric/hex)
  ├─ "guest-123"                  ✗ (too short, has prefix)
  ├─ "507f1f77bcf86cd799439011abc" ✗ (25 chars, too long)
  ├─ "507f1f77bcf86cd79943901"     ✗ (23 chars, too short)
  └─ "507g1f77bcf86cd799439011"    ✗ (contains 'g', not hex)
